# mem-cache 本机压测报告

2026-11-24 · Apple M5 Pro（15 核）、24 GB · Darwin 25.6 arm64 · Go 1.25.14 · 性能用例固定 GOMAXPROCS=8。被测 mem-cache 提交为 `a56ddf4f8c8b9efe77ce18a93d587d60b93b9218`。原版对照为 gotap/caches 的 ebf728076160。

## 主要结果

1. Simple 满容量且全部 TTL 有效时，新键写入随容量增长显著变慢。10 万条时每秒接纳 1,545 个新键，ARC 在同条件下为 786,860 个。Simple 在锁内遍历 map 寻找已过期或永久条目，此负载每次都会扫完整张表。

2. ARC 在 64 并发下每秒完成 145 万次单键命中、24.25 万次 32 键全命中批读。后者相当于每秒读取约 776 万个 key。两者的请求 P99 分别为 0.508 ms 和 1.999 ms。

3. 同版本替换为 OTel 空实现后，ARC 的 64 并发单键命中吞吐约为 286 万次/秒。单独采集的同负载 mutex profile 中，命中计数器的 OTel 聚合调用栈占累计锁等待的 74.09%。

4. 同一 key 的同步 Get 每轮 256 个并发未命中合成 1 次回源。64 个并发 MGet 读取同一组 32 个冷 key 时，后端收到 64 批、累计 2,048 个 key。故障集中发生时，本地日志输出与实际 loader 错误逐次对应。

## 压测方法

闭环矩阵含 71 组条件，每组独立预填缓存、运行 0.5 秒、共 3 轮；轮内顺序随机。共完成 175,465,815 次 API 操作，采集 28,644,902 个延迟样本。表中每列取三轮中位数。每个 worker 连续发请求，操作数按包含压测循环、随机选键和校验的实际墙钟时间折算。

闭环用例使用整数 key，值为共享小字符串，TTL 为 1 小时。单键读和批量全命中读均匀随机取样。90/10 混合指 90% 读、10% 覆盖已有 key。满容量写入为持续插入全新 key。32 键部分命中批次为 24 个热键和 8 个新键，loader 在内存中立即响应。延迟计入调用时等待锁的时间，批量取每次 API 调用的延迟。常规用例每 16 次采样一次，满容量写每次采样。闭环分位数按细分对数桶上界近似，桶宽至多为所在二次幂区间起点的 1/32。

定速测试由独立 Go 模块通过公开 API 调用。每个 key 为字符串，每个值为独立的 256 字节对象。ARC 预热 65,536 个条目和 1,024 组查询，32 个工作协程，调用方等待队列容纳 256 个请求。发压方按计划到达时间提交、队满立即丢弃。每 4 个完成请求采样一次实际分位数。先跑两轮、每档 3 秒，再对两个中间档各跑 15 秒。端到端延迟从计划到达算至返回，含本机调度、发压和排队；丢弃的请求单独列示。

Doku 指标使用该版本 dmetrics 的本地 SDK 与 ManualReader；空实现仅通过隔离的测试进程替换 instruments。两者均执行缓存自己的属性构造和统计代码。本报告覆盖进程内指标聚合、Doku 本地真实 logger、合成回源。远端 OTLP 传输、网络、业务编解码耗时及服务端容量需按实际环境另外计量。

## 并发一致性、回源与日志

原仓 55 个顶层测试通过，完整套件在 race 检测和随机顺序下通过 3 轮，覆盖率 90.7%。go vet 和 go mod verify 均通过。跨模块调用验证了公开导入路径；压测临时 go.mod 固定到同一份 Git 快照。

并发状态校验在 4 种策略上分别以 16 个 worker 混合执行读写、批量写入/读取、删除、快照、调整假时钟与 Purge。3 轮共 1,179,648 个随机步骤，每轮每策略 12 次静止点核对容量、驻留值及策略索引。race 检测无报告。

同键冷启动和 TTL 过期共 98,304 次请求，384 次源加载，每个波次 256 请求合为 1 次。每轮另有 128 个等待者取消，原 loader 仍完成并写入。跨批次重叠未命中每轮发出 64 批、2,048 个回源 key，唯一 key 32 个。

原仓指标测试逐项对比真实 OTel Reader 的 6 个指标、计数和公共标签。另用独立调用方并发触发 3,200 次独立回源失败，得到 3,200 条 mem_cache.load_failed，64 个合成 trace 各 50 条，策略、操作、错误及 span 字段匹配，原始缓存 key 出现次数为 0。故障期可按实际失败的 loader 次数估算这类日志量。

## 复跑

在 mem-cache 仓库根目录执行下列命令。脚本使用 Git 快照、Go、Python 3 和独立临时目录，输出路径会打印至终端。默认验证当前 HEAD 的缓存和 Doku 指标，运行时需要能够取得 go.mod 指定的依赖。并发一致性和回源检查需要支持 Go race detector 的环境。

```bash
./benchmarks/run.sh
```

复现本报告的 71 组矩阵时，指定被测提交并启用原版对照。此模式还需可读取指定版本的 gotap/caches，或本机 Go 模块缓存已包含该版本。

```bash
REV=a56ddf4f8c8b9efe77ce18a93d587d60b93b9218 WITH_GOTAP=1 ./benchmarks/run.sh
```
